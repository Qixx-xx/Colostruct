# 前端五分钟介绍（讲稿）

> 纯口语稿，念下来约 5 分钟。方括号里是时间提示，不用念出来。
> 如果时间被压到 3 分钟，删掉「三、做了什么」里的第 2、3 点，其余保留。

---

**[约 20 秒 · 开场]**

我讲一下前端这块从接手到现在做了什么、卡在哪里，最后说联调需要大家配合什么。分三块：换掉 Streamlit 的过程、已经解决的问题、还有等后端的三件事。

---

**[约 50 秒 · 起点]**

最开始这套东西是 Streamlit 写的，大概七百行 Python，三个页面：上传音频、审校十五个字段、导出 Markdown。Streamlit 的好处是纯 Python，不用碰前端；但问题也很明显，它其实控制不了页面，双栏布局、音频时间轴、中文排版这些东西都得绕。所以这次整体迁到了 Vue 3。

现在代码在 `frontend/colostruct_v3` 下面，老的 Streamlit 版完整保留在 `legacy_mvp` 里，两边可以对着看。

---

**[约 70 秒 · 一个必须说清楚的概念]**

这里有个概念必须先讲，因为它直接决定联调时的行为，也是最容易误会的地方。

Streamlit 的做法是：你点一下按钮，它把整个脚本从头到尾重跑一遍，整个页面重画。所以数据必须存在 session_state 里，代码里到处是 `st.rerun()`。

Vue 不是这样。页面画出来之后就一直活着，你点按钮，代码只是改了一个变量，Vue 发现用到这个变量的地方变了，就只更新那一小块。原来那十来处 `rerun` 全部消失了——这不是漏写，是它根本不需要。

一句话：**Streamlit 是整页重画，Vue 是哪里变了改哪里。** 所以数据现在集中放在一个叫 store 的文件里，取代了原来的 session_state。

---

**[约 90 秒 · 做了什么]**

具体做了四件事，我按重要性讲。

第一，拆结构。原来三个页面文件加一个公共库，现在按职责分开：文案单独一个文件，全局状态一个文件，纯数据函数一个文件，生成 Markdown 一个文件，网络请求一个文件，剩下五个组件对应三个页面加时间轴和字段卡片。改文字只用动文案文件，不会碰到逻辑。

第二，把时间轴重写了。原来那个音频时间轴是塞在一个 190 像素高的 iframe 里，用 Python 拼 JavaScript 字符串生成的，还得专门转义防止脚本标签被提前闭合。现在是一个普通组件，点一下跳转就是设置播放位置然后播放。

第三，加了一个自检脚本。因为"能编译"不等于"和原版一致"，所以写了个命令，29 项检查，会逐字符比对新旧版本导出的 Markdown 是不是完全一样，还会验证片段索引、HTML 转义、音频地址解析。改完代码跑一下，十秒钟。

第四，处理了组员反馈的三条问题。核对下来是这样：证据按钮点了不跳转播放，这条 Vue 版也继承了——因为原版那两个回调只改高亮、从来不碰音频，我迁移时原样搬过来了，现在修好了；macro 和 micro 音频只有长度没声音，是因为后端返回的音频地址是文件系统路径，浏览器当网址去请求必然找不到，现在前端会自动把它转成服务器上能访问的地址；第三条"上传 diagnosis 之后 macro 和 micro 预览消失"，前端查下来没有这个 bug——三个上传框和两个文本框都是无条件渲染的，真正原因是后端只返回了 diagnosis 一个模块。现在界面会弹一个横幅把这种矛盾直接说出来。

---

**[约 90 秒 · 卡在哪]**

接下来是还没解决的问题，主要都在后端。

**最关键的：接口层已经有，但需要和前端对齐。** 仓库根目录有 `api.py`，是 FastAPI 网关，已经挂了 `/api/process`、`/api/health` 和音频回放。我之前说"没有 HTTP 服务"是错的，那是基于我手上不完整的副本判断的，这里更正一下。所以现在的任务不是从零写网关，而是把它和前端的契约对一遍：请求字段名、返回结构、十五个字段的 key、三种状态。对齐之前，前端只能靠上传页那个开发开关加载演示数据来看界面。

**第二，必须按模块分别返回。** 那个处理函数一次只处理一组音频、返回一个模块的数据。如果 HTTP 层图省事只调一次，把 macro 和 micro 写死成"未上传"，界面上就会变成——左栏只剩 Diagnosis 一个标签页，右栏 Macro 和 Micro 只剩一句"未上传"。刚才说的第三条反馈就是这个现象。

**第三，必须把 storage 目录挂载成 `/storage`。** 一行代码的事。不挂的话音频文件请求不到，播放器只显示时长、不出声。

另外两条约定：单个模块失败要用正常状态码加失败标记表达，不能用 500，否则一个模块挂掉整页都挂；音频地址最好直接返回能访问的完整地址，前端虽然兼容文件路径，但那是权宜之计。

---

**[约 40 秒 · 联调怎么配合]**

联调只需要对齐三件事。

**端口**：后端 8000，前端 5173，转发已经配好了，后端不用配跨域。

**契约**：以 `API_CONTRACT.md` 为准，里面写了请求字段名、返回结构、十五个字段的 key、三种状态，还附了一份最小可用的参考实现。

**顺序**：建议先让接口能返回一个最简的 JSON 把链路打通，再往里填真实数据。别一上来就接大模型。

还有一点要说明：**我这边跑不起开发服务器**，改代码只能验证编译和自检，音频播放、大文件上传这些必须在浏览器里才能确认。所以验收需要大家帮忙点一遍，清单在迁移说明第七节，十八条。

---

**[约 15 秒 · 收尾]**

总结一句：前端功能已经完整，三个页面、十五个字段、时间轴联动、导出都能走通，用演示数据可以完整演示。现在唯一的硬阻塞是**接口对齐**——`api.py` 的返回要和前端的契约一致。

---

## 附：被追问时的三句话

- **为什么不用 Streamlit 了？** 它控制不了页面布局和交互，时间轴、双栏、中文排版都得塞 iframe 和 HTML 字符串绕。
- **前端会不会拖慢 AI？** 不会。前端只负责收文件、发请求、画结果，AI 全在后端。
- **为什么我这儿看不到真实数据？** 接口还在对齐，现在只能走演示数据开关。
